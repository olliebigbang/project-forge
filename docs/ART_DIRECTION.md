# Project Forge — M1A 美术方向

版本：0.1

适用阶段：M1A 确定性武器编译器

文档性质：视觉规则与原型验收基线，不是正式资产清单

## 1. 状态说明

- **CONFIRMED**：来自 GDD 或 M1A 验收要求，当前必须遵守。
- **ASSUMPTION**：为让原型可落地而提出的当前视觉假设，可在不改变核心玩法的前提下调整。
- **TO VALIDATE**：需要通过手机实机、可读性测试或玩家测试验证。
- **TBD**：本阶段不决定。

本文只定义原创 2D 手绘卡通方向。M1A 不批量制作正式资产，不替换现有占位素材，也不以美术完善度阻塞武器编译器和战斗行为验证。

## 2. 核心视觉命题

### 2.1 “一张速写真的开始战斗”

- **CONFIRMED** 玩家画出的原始线条是武器身份的核心，不能被预制精美武器完全覆盖。
- **ASSUMPTION** 世界采用“活起来的锻造速写”语言：角色和目标是稳定、清楚的手绘卡通形；玩家武器保留更自由、更个人化的线条；元素与攻击动作像刚从草图中迸出的彩色批注。
- **CONFIRMED** 机械差异必须首先由轮廓、轨迹、节奏和命中反馈表现，不能只靠换颜色。
- **CONFIRMED** 视觉优先级依次为：可操作角色、危险/攻击轨迹、目标状态、玩家武器轮廓、装饰细节。
- **TO VALIDATE** 轻微纸张颗粒是否会增强“手绘”感而不降低手机端清晰度。

目标感受不是“系统替玩家画了一把更漂亮的武器”，而是“系统读懂这张画，并让它以合理方式动起来”。

### 2.2 情绪与边界

- **ASSUMPTION** 基调为勇敢、机灵、带一点实验室失控感；避免血腥、阴暗写实和军事仿真。
- **ASSUMPTION** 造型允许夸张、歪斜和手工不完美，但交互轮廓与伤害范围必须准确。
- **CONFIRMED** M1A 不制作正式关卡、叙事场景或高成本逐帧动画。
- **TBD** 正式世界观、时代、地域文化、角色姓名与阵营。

## 3. 形状语法与剪影

### 3.1 全局形状语法

使用三类基础形状建立无需文字也能理解的视觉语法：

| 形状 | 含义 | 建议用途 |
| --- | --- | --- |
| 圆与软弧 | 可接近、弹性、普通状态 | 主角主体、普通/成群目标、区域范围预告 |
| 方与厚块 | 稳定、阻挡、重量 | 盾牌目标、地面、重型代价反馈 |
| 三角与尖线 | 方向、速度、穿透、危险 | 投射物箭头、刺穿轨迹、火焰尖端 |

- **CONFIRMED** 攻击形式必须拥有不同的轮廓和运动路径。
- **ASSUMPTION** 主角以圆形为主、方形为辅；阻挡目标以方形为主；攻击危险以三角形为主。
- **TO VALIDATE** 在 844×390 与 915×412 CSS 像素横屏尺寸下，去色截图中是否仍可仅凭剪影区分五种攻击。

### 3.2 尺寸层级

- 主角主体高度以战斗可视区域高度的约 18%–24% 为原型范围。
- 武器静止轮廓应至少达到主角高度的 35%，过小线稿通过等比放大而不是加粗成团。
- 普通目标与主角主体接近；成群目标单体约为普通目标的 45%–60%；盾牌轮廓至少覆盖其本体正面高度的 70%。
- 关键轨迹的手机端可见厚度建议不低于 4 CSS 像素；命中闪光的最短可见时间建议不低于 80 ms。
- **TO VALIDATE** 以上尺寸在不同 DPR、浏览器地址栏和安全区组合下的实际可读性。

## 4. 线条语言

### 4.1 环境、角色与目标

- **ASSUMPTION** 使用深蓝黑而非纯黑外轮廓，形成亲和的墨线感。
- 外轮廓约为内部线的 1.5–2 倍；转折处略有压感变化，但碰撞边界附近不使用会误导距离的毛刺。
- 内部细节限制在能说明朝向、受击面或状态的必要线条；小尺寸不画指节、五官纹理和密集材质线。
- 阴影优先使用一块清楚的色面或 2–3 根稀疏排线，不使用连续灰阶写实渲染。

### 4.2 玩家绘画武器

- **CONFIRMED** 保留玩家原始笔画的相对形状、主要转折、断点与手绘特征。
- **ASSUMPTION** 武器由三层组成：玩家线条“墨芯”、1 层窄的可读性描边、位于线条下方的元素光/材质效果。
- 可做轻微等比缩放、居中和统一线宽补偿；不得擅自把线稿重绘为预制刀、枪或知名武器。
- 对非常淡、细、短或重叠严重的笔画，只补可读性描边，不补想象出的复杂结构。
- 握点与朝向尚未可靠推断时，用不抢眼的中性小节点表示系统握点；不要假装已理解不存在的刀柄。
- **TO VALIDATE** 玩家能否在生成后 3 秒内指出自己原图中的至少两个特征。
- **TBD** 生产阶段的自动平滑强度、断线连接规则和材料填充算法。

## 5. 配色系统

### 5.1 基础色板（原型建议）

| 角色 | 主色 | 辅色 | 轮廓/深色 | 作用 |
| --- | --- | --- | --- | --- |
| 背景纸面 | `#F3E8CF` | `#D9C8A6` | — | 温暖、低对比，不抢战斗信息 |
| 场地/平台 | `#67707A` | `#929AA1` | `#232B3A` | 稳定中性基座 |
| 主角 | `#3A9D9A` | `#F1B24A` | `#20283A` | 冷暖双识别、与四元素分离 |
| 普通目标 | `#8B73B8` | `#C7B7E3` | `#2D2940` | 易与主角区分 |
| 盾牌目标 | `#68758D` | `#B9C0CC` | `#252B38` | 重量与阻挡感 |
| 成群目标 | `#A678A4` | `#D7B5D1` | `#35243A` | 同类成组但不等同元素色 |

- **ASSUMPTION** 色值是 M1A 原型基准，不是品牌最终色。
- **CONFIRMED** 可交互内容与背景须保持明确明度分离。
- **TO VALIDATE** 普通文本和大文本分别达到 WCAG 2.2 AA 对比度目标；游戏内非文本关键图形尽量达到 3:1。

### 5.2 四元素不是四种换色

| 元素 | 主色建议 | 次色建议 | 形状语言 | 运动语言 | 命中残留 |
| --- | --- | --- | --- | --- | --- |
| `normal` | 象牙白 `#F7F0DC` | 石墨蓝 `#445064` | 实心笔触、短速度线 | 直接、一次收束 | 小型星芒/尘点 |
| `fire` | 橙红 `#F05A3C` | 金黄 `#FFC857` | 上尖下宽的火舌、三角碎屑 | 上扬、抖动、余焰 | 短暂焦色刻痕 |
| `ice` | 青蓝 `#49BFD1` | 近白蓝 `#D9FBFF` | 菱面、六角碎片、尖晶 | 清脆扩张后骤停 | 裂纹/薄霜环 |
| `electric` | 亮黄 `#FFE45E` | 紫蓝 `#7766E8` | 锯齿分叉、节点圆点 | 跳跃、间歇闪烁 | 2–3 段分叉余弧 |

- **CONFIRMED** 元素必须同时依靠颜色、形状和时序识别。
- `normal` 不应看起来像“没有特效的失败版本”；它以扎实墨击、清楚重量和低噪声获得辨识度。
- `fire` 不用整屏红色滤镜；`ice` 不把目标整体染成低对比浅蓝；`electric` 闪烁不得持续高频全屏反转。
- **TO VALIDATE** 灰度、红绿色弱、蓝黄色弱模拟下的元素识别率。
- **TBD** 正式后处理、粒子纹理和屏幕光照方案。

## 6. 主角方向

### 6.1 角色概念

- **ASSUMPTION** 主角原型为“小个子创想锻造者”：短而稳定的身体、前倾动作线、醒目的护目镜或额前轮廓、一只较大的绘画/锻造手套；不绑定性别与具体文化。
- **ASSUMPTION** 主角剪影由大圆头/上身、短方形躯干和一处斜向披布或工具带组成，左右朝向在小屏幕仍明显。
- **CONFIRMED** 武器必须比服装装饰更抢眼，手部与握点不能被披风或大袖遮挡。
- **TO VALIDATE** 静止、移动、攻击和受击四个姿态在纯黑剪影中能否区分。
- **TBD** 主角姓名、脸部细节、服装叙事和正式比例。

### 6.2 原型动画规则

- 待机：低幅度呼吸和手腕微调，不让武器持续晃到难以辨认原笔画。
- 移动：身体前倾、脚部两拍循环；大武器的移动代价可用更深前倾与拖后表现。
- 攻击：先给 80–140 ms 可读预备，再释放主轨迹；快速武器可缩短但不可完全省略方向提示。
- 受击：单帧清晰压缩形变加短后移，不长时间遮住玩家攻击结果。
- 重新锻造：旧武器线条回收成少量墨点，新线条按原始笔画顺序快速显现；避免像开宝箱抽卡。
- **TO VALIDATE** 原型动画时长需与实际冷却和 Power 代价一致，不能为了好看制造“假快”或“假慢”。

## 7. M1A 目标视觉规则

目标是测试攻击机制，不是正式怪物。每类目标必须在静止帧中显示其核心问题。

### 7.1 移动目标

- **ASSUMPTION** 使用前倾水滴/椭圆主体与一对明显的滚轮脚或弹簧脚，移动方向由鼻尖形和 2–3 根短速度线表达。
- 路径转向前短暂压缩，转向后伸展，便于判断移动而非瞬移。
- 受控状态时速度线被对应元素形状替换，例如冰晶卡住脚、闪电节点短暂钉住位置。
- **CONFIRMED** 不靠颜色区分“正在移动”和“停止”。

### 7.2 盾牌目标

- **ASSUMPTION** 本体较小，正面有高而厚的非对称矩形盾；盾面用三道横纹表现层级，背面暴露圆形软轮廓。
- 盾牌朝向必须始终明确：正面轮廓平直、背面轮廓圆软，并以地面小箭头辅助调试。
- 正面被减伤时显示低沉方形火花和盾面波纹；绕后或有效穿透时显示穿过盾后的出口闪光。
- **CONFIRMED** 盾牌不是“血更厚”的同款目标，阻挡反馈必须与本体受伤反馈不同。

### 7.3 成群目标

- **ASSUMPTION** 采用 4–6 个同语系小目标，每个用一处轮廓缺口、顶部短角或表情点位略作差异。
- 群体成员间保留至少一个轮廓线宽的负空间；重叠时使用前后明度而不是大量外发光。
- 区域攻击命中多个单位时，数字与闪光错开 40–80 ms，避免在手机上叠成不可读白块。
- **CONFIRMED** 单体、群体总伤害和击中数量必须可从反馈中区分。

### 7.4 普通固定目标

- 保留为中性基准：圆角方体、中心靶心和简单受击变形。
- 不持盾、不移动、不携带元素色，以便比较五种攻击的纯行为差异。

## 8. 五种攻击形式

五种攻击应当通过“起手剪影 + 主路径 + 命中形状 + 收尾节奏”四项形成独立身份。

### 8.1 `melee_slash`

- 起手：武器回收到身体后侧，角色重心压低。
- 主路径：单个宽而渐细的月牙弧，弧根厚、弧尖细；玩家线稿随手部旋转，不被弧光覆盖。
- 命中：接触点出现短促扇形墨裂和横向推力线。
- 收尾：弧光立刻消退，角色回正；高伤害版本以更长回收体现代价。
- 可读关键词：近、弧、挥。

### 8.2 `straight_projectile`

- 起手：武器朝同一方向短暂压缩/聚光。
- 主路径：尺寸稳定的单一弹体沿直线离开；尾迹由平行短线组成，不画回程弧。
- 命中：小型正向爆点，方向与飞行线一致。
- 收尾：弹体命中或到达射程后消散；射速代价由发射间隔和聚光时间显示。
- 可读关键词：直、快、单向。

### 8.3 `boomerang`

- 起手：武器或其投影绕握点半圈蓄势。
- 主路径：弯月/双翼弹体沿明显的外出弧线飞行，再沿另一侧弧线返回；轨迹以点划线或渐淡圆点强调闭环。
- 命中：外出与回程命中使用同形不同朝向的旋转星芒；返回角色时收成小圆环。
- 收尾：必须看见回到玩家或回程结束，不能伪装为普通弹体二次生成。
- 可读关键词：旋、弧、去回。

### 8.4 `area_blast`

- 起手：目标位置或玩家周围出现细虚线预告圆，圆心有 3 段向外刻度。
- 主路径：由内向外扩张的环形波，中心保持较清楚，避免用实心光球遮住群体目标。
- 命中：范围内目标各自产生小型径向反馈，同时地面短暂保留范围边界。
- 收尾：环线碎成稀疏颗粒；大范围或强控制版本以更长冷却/更低单体冲击反馈代价。
- 可读关键词：圈、扩、群。

### 8.5 `piercing`

- 起手：长而窄的方向指示沿攻击轴对齐，武器做一次向后拉直。
- 主路径：针状弹体或窄束线穿过多个目标；主线前端最亮，沿途不产生会误读为停止的大爆炸。
- 命中：每个目标出现入口点和相反侧出口短线；最后一个命中后仍延伸一小段以证明“穿过”。
- 收尾：路径快速从尾端擦除；强穿透能力的代价由较窄命中带、较长蓄力或较低单次伤害表现。
- 可读关键词：窄、贯、连续。

### 8.6 去色验收表

| 攻击 | 独有主形 | 独有运动 | 不应混淆为 |
| --- | --- | --- | --- |
| 近战挥砍 | 宽月牙 | 围绕角色单次旋转 | 区域圆环 |
| 直线投射 | 稳定小弹体 | 单向直线 | 穿透长束 |
| 回旋 | 双翼/弯月弹体 | 外出并返回的闭环 | 两发直线弹体 |
| 区域爆发 | 空心扩张圆环 | 径向外扩 | 大号命中闪光 |
| 穿透 | 细针/长束 | 贯穿多个目标继续前行 | 普通弹体逐个消失 |

## 9. Power 代价的视觉反馈

- **CONFIRMED** 所有强力能力必须自动产生相应代价；视觉、动画和 UI 必须忠实反映运行时计算结果。
- 高伤害/慢速：更重的预备压缩、更强单次冲击、更长且可见的回收，不通过镜头剧烈抖动伪造伤害。
- 大范围/低单体伤害：范围圆更宽，但单个目标的命中星芒更小。
- 强控制/长冷却：状态形状更清楚，能力按钮冷却环更长；不让残留特效看起来仍在持续伤害。
- 高射程/低速度：轨迹边界可见、弹体明显慢；不拉长尾迹使其误读为高速。
- 巨型/移动代价：武器线稿等比放大，角色移动时身体后拖；不裁掉武器尖端来隐藏尺寸。
- **CONFIRMED** UI 显示的代价、动作表现与实际战斗数值必须来自同一份 `WeaponSpec`/预算结果。
- **TO VALIDATE** 玩家不阅读数值时，是否能从动作预测“强在哪里、代价是什么”。

## 10. UI 方向

### 10.1 视觉层级

- **ASSUMPTION** UI 像贴在工作台上的手绘标签：圆角纸片、单层深色描边、极轻偏移阴影；避免仿制具体游戏的羊皮纸或锻炉 UI。
- 一级：绘画区、生成/攻击主按钮、战斗区。
- 二级：武器名称、攻击形式、伤害、元素、效果、弱点/代价。
- 三级：日志、预算明细和修正原因，可折叠或放在调试面板，不遮挡战斗。
- **CONFIRMED** 攻击形式、元素、特殊效果和弱点均需以文字展示；图标只作辅助。
- **CONFIRMED** “重新锻造”必须与“攻击”在位置、形状和文案上明显不同，避免误触清除作品。

### 10.2 图标语法

- 近战：一条粗弧加短握柄。
- 直射：圆点加直箭线。
- 回旋：双向弧箭头加弯月。
- 区域：同心空心圆。
- 穿透：直线连续穿过三个小圆。
- 普通：实心墨星；火：火舌；冰：六角晶；电：分叉锯齿。
- **CONFIRMED** 图标不得仅靠元素色表达含义，必须有独立外形。

### 10.3 字体与数字

- **ASSUMPTION** 标题可使用带少量手写感但字腔清楚的字体；正文、数值和调试信息使用高可读无衬线体。
- 中文最小正文建议 16 CSS px；关键武器数值建议 18–22 CSS px；触控按钮文字不低于 16 CSS px。
- 数值变化同时使用符号/箭头与颜色，例如 `伤害 32 → 24`，不能只从绿变红。
- **TBD** 正式字体授权与多语言排版方案。

## 11. 移动端横屏约束

- **CONFIRMED** 操作不能依赖悬停、右键或键盘。
- 所有主要触控目标建议至少 48×48 CSS px，目标之间至少保留 8 px；绘画板从边缘内缩，减少系统返回手势冲突。
- 尊重左右安全区和底部手势条；关键按钮、生命/状态和重新锻造入口不得贴屏幕物理边缘。
- 绘画阶段优先保证画布和生成按钮；战斗阶段优先保证角色、目标、移动与攻击按钮，不要求一次显示全部预算日志。
- 玩家手指覆盖画布时，当前笔迹应在触点前后保持连续；不使用跟随指尖的大型装饰光圈。
- 粒子数量以“少而有形”为原则；低性能模式可减少粒子，但不得删除攻击的主形和命中反馈。
- 屏幕震动限制为局部、短时、低幅；移动浏览器默认关闭强震动选项。
- **TO VALIDATE** 844×390、915×412、1280×720 三个视口以及带刘海/圆角安全区的布局。
- **TO VALIDATE** 单手按住移动、另一手攻击时，手指是否遮挡目标或武器轨迹。

## 12. 可访问性与舒适度

- **CONFIRMED** 元素、攻击类型、成功/失败、盾牌阻挡、修正和代价不能只靠颜色传达。
- 提供清楚文字标签；状态图标保留固定位置和固定轮廓。
- 重要反馈至少组合两种通道：形状 + 动画、文字 + 图标或颜色 + 轮廓。
- 电元素不使用高频全屏闪烁；任何大面积闪烁控制在安全频率之外并提供“减少闪光”选项规划。
- 支持“减少动态效果”规划：取消镜头震动和连续漂浮颗粒，但保留起手、主路径和命中关键帧。
- 避免细密棋盘、连续高对比条纹和长时间屏幕倾斜。
- 绘画板提供高对比笔迹，后续应考虑线宽选择和撤销功能；M1A 是否实现由主 Agent 的验收范围决定。
- **TO VALIDATE** 色觉模拟、200% 浏览器缩放、系统大字体和减少动态偏好。

## 13. 原创性、反临摹与 IP 规则

### 13.1 必须遵守

- **CONFIRMED** Project Forge 是全新独立项目，不复用 Cat Battle 或任何旧项目的代码、名称、设定、美术、资产、平衡数据或开发方向。
- 不以任何现有游戏、动画、电影、漫画、玩具品牌、艺术家或在世插画师作为“照着画”的风格目标。
- 不复刻知名角色的独特轮廓、服装组合、面具、徽记、配色排列、标志性武器或 UI 构图。
- 不导入来源不明的素材、字体、笔刷、纹理、图标和音效；所有第三方资源必须记录来源、许可证、作者和修改要求。
- 玩家输入若要求已知角色、品牌武器或标志，应保留抽象玩法意图，但移除受保护名称与独特识别特征，并在日志中记录转换原因。
- 安全转换示例：“某知名英雄的锤子”可解释为“短柄重击武器 + 电元素 + 慢回收”，不得复现该作品的外形、名称、铭文或配色组合。

### 13.2 原创检查清单

每个进入生产候选的角色、目标、武器处理或 UI 方案须回答：

1. 其轮廓是否在去色后仍明显依赖某个知名 IP？
2. 去掉颜色与标志后，是否仍复制了独特服装/武器组合？
3. 参考板是否由多个通用来源和现实材质组成，而非单一作品截图？
4. 是否保留了玩家自己的笔画，而不是套上知名武器外壳？
5. 所用字体、笔刷与纹理是否有可追溯授权？
6. 是否能用 Project Forge 自己的形状语法解释每一项设计选择？

任一答案不安全时，该方案保持为 **TO VALIDATE**，不得进入正式资产替换。

## 14. 动效与战斗可读性预算

- 同一命中点同时出现的主效果最多一个；元素效果是附着层，不再叠第二个大爆炸。
- 屏幕内存在大量群体目标时，远离玩家的次要粒子减少，轨迹和碰撞反馈不减少。
- 伤害数字按目标聚合或错峰，避免每帧喷字；穿透必须仍可数出命中过几个目标。
- 状态持续效果限制在目标轮廓外侧或脚下，不遮住盾牌朝向与本体受击。
- 前景、角色、攻击、目标四层使用稳定的绘制顺序；元素光不越过 UI。
- **ASSUMPTION** 原型优先 60 fps，允许低性能模式减少装饰层以维持输入响应。
- **TO VALIDATE** 中档手机 Web 浏览器上 6 个群体目标、穿透和元素残留同时出现时的帧率与可读性。
